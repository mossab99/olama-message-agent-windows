# Olama Message Agent — Windows Sender Client

A lightweight, zero-dependency C# .NET Framework 4.8 Windows tray application that acts as a local gateway for dispatching campaign and test messages via KDE Connect.

---

## 🛠️ Build & Compilation Instructions

### Prerequisite Build Environment
This project requires **Visual Studio 2022 Build Tools** (specifically the C# Roslyn Compiler `csc.exe` and `.NET Framework 4.8 targeting assemblies`).

### Option A: Direct Roslyn Compilation (Local Dev Recommended)
If your local Visual Studio Build Tools lack the full Developer targeting packs for `.NETFramework,Version=v4.8`, MSBuild will report `error MSB3644: The reference assemblies for .NETFramework,Version=v4.8 were not found`. 

To compile successfully without requiring Developer targeting pack downloads, compile **directly** using the Roslyn compiler which compiles against the standard system GAC runtime assemblies:

```powershell
& "C:\Program Files (x86)\Microsoft Visual Studio\2022\BuildTools\MSBuild\Current\Bin\Roslyn\csc.exe" /target:winexe /out:bin\Release\OlamaMessageAgent.exe /r:System.dll,System.Windows.Forms.dll,System.Drawing.dll,System.Net.Http.dll,System.Web.Extensions.dll,System.Security.dll *.cs
```

### Option B: Build via MSBuild (Requires Targeting Pack)
If the `.NET Framework 4.8 Developer Pack` is installed on the machine, you can run:

```powershell
& "C:\Program Files (x86)\Microsoft Visual Studio\2022\BuildTools\MSBuild\Current\Bin\MSBuild.exe" /p:Configuration=Release /t:Rebuild OlamaMessageAgent.csproj
```

## 📂 Local Storage & Security Specifications

To prevent accidental git check-in of API credentials, all configurations are stored strictly outside the codebase directory:

* **Settings File Location**: `%LocalAppData%\OlamaMessageAgent\settings.json`
* **Agent Logs Location**: `%LocalAppData%\OlamaMessageAgent\agent.log`

### 🔒 API Secret Key Protection (DPAPI)
The API Secret Key generated by WordPress is sensitive. To protect it on the local system:
1. The key is encrypted under the Windows user profile utilizing the **Windows Data Protection API (DPAPI)**:
   `System.Security.Cryptography.ProtectedData.Protect`
2. It is saved in the JSON settings file under `ProtectedApiKeyBase64`.
3. Plaintext secrets are never written to disk, preventing access by unauthorized local users.
4. **Log Redaction**: The logger actively sanitizes all strings and replaces matching `olama_agent_` structures with `[SECRET_KEY_REDACTED]`.

## 🔄 Core Functional Flows

1. **Heartbeat Timer (60s default)**: Light check verifying internet connectivity and CLI path existence. Dispatches telemetry back to WordPress.
2. **Diagnostics Timer (300s default)**: Runs discovery scanning (`kdeconnect-cli.exe --list-devices`) to fetch paired Android phones and uploads the telemetry array to `/wp-json/olama-messages/v1/agent/diagnostics`.
3. **Manual Test Panel**: Accessible via the tray menu. Input a phone number (Jordan E.164 pattern: `+9627XXXXXXXX`) and a message (max 160 characters) to trigger immediate dispatch and inspect command stdout/stderr.


## Dispatch protocol 2 recovery

Use this agent with Olama Messages 4.0.13 or later. Deploy the plugin before launching this version. Both sides reject incompatible dispatch protocols before reserving SMS work.

Each queue reservation has a unique attempt ID. The agent persists an unknown outcome before invoking KDE, then replaces it with the observed result. On restart it reports the saved outcome without sending again. CLI timeouts and uncertain errors require phone-history review on the WordPress campaign progress page. A successful command means submitted via KDE; it does not confirm recipient delivery.

The shared local limiter persists submission intents in `sms-rate-history.json`. Campaign and manual sends use the same limit: at least 10 seconds between intents, with at most 360 per rolling hour. The server independently enforces device limits across agent registrations. Do not clear pending outcomes or rate history to bypass these checks.

Run `./tests/run-recovery-tests.ps1` from this repository for synthetic recovery tests. They compile a fake CLI and use a localhost HTTP fixture; no real SMS is sent.
